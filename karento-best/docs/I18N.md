# Signature languages and dealer facts

Signature renders English and Bulgarian through `src/lib/i18n`. Stable message keys describe UI roles. The catalogs contain language text; dealer names, contacts, addresses, vehicle titles and listing facts remain at the typed `content.ts` and vehicle-data boundaries.

`hooks.server.ts` resolves one explicit valid `?lang=` value, then the saved `signature_locale` preference, then the dealer default, with English as the documented fallback. It stores the resolved locale in request-local `App.Locals`. The server layout returns that locale and the compiled SvelteKit mount. Each rendered layout creates its own typed context; the client follows reactive layout data during navigation. There is no process-global visitor locale or DOM text replacement.

Use `const locale = useLocale()` in a component. `locale.t("navigation.vehicles")` resolves a stable key; parameterized keys require their declared values. `locale.text(message("header.about.title"))` handles typed message references in shared data. Keep actual names and factual descriptions as data rather than looking up English phrases at runtime.

Use `locale.href("/vehicle?id=actual-id#photos")` for ordinary internal links. It adds the selected language, keeps the vehicle ID and other query values, and applies the compiled mount once. Hash-only links keep the current page; external links and telephone/email links stay unchanged. GET search forms include one `lang` input and must exclude a previous `lang` from preserved parameters. The language switcher retains the current route, ID, filters and hash.

Use `locale.number`, `locale.money`, `locale.date` and `locale.count` for UI values. A listing's declared currency is preserved; changing language never converts EUR to BGN. `presentVehicle` formats explicit numeric/code facts and uses translated unknown labels when facts are absent. Unqualified legacy strings remain a data fallback, so new dealer adapters should provide the optional numeric and canonical-code fields. Empty observation dates remain empty rather than becoming invented dates.

`DealerContent.businessPreview` selects the factual dealer view. It carries snapshot date/count, city/country/currency and a contact-before-visit flag without per-dealer language paragraphs. Native consumers choose shared translated text, retain reviewed business facts and omit unsupported reference rental promotions, ratings, staff and newsletter claims. Preview forms explicitly state that information was not sent or saved.

To add a language, create a catalog with exactly the English keys and interpolation parameters, register its label, Intl locale and messages in `locales.ts`, and run the catalog, request-isolation, route/query, currency and rendered checks. The locale type, switcher and native translation consumers follow the registry. Dealer release manifests must separately enable and qualify that language before public fleet publication.

The aggregate `catalogs/en.ts` and `catalogs/bg.ts` assemble paired, literal catalog modules. `catalogs/core.ts` holds the core `coreEn` and `coreBg` exports. Native release review declares each literal pair with its actual exported binding names; the source parser never executes aggregate imports or spreads. Catalog completeness checks cover all assembled runtime keys and interpolation parameters. Reference service and product records can carry optional stable message keys while custom dealer text remains factual data.

Run the exact Node version in `.node-version`. SvelteKit 3 writes project-specific TypeScript configuration into `node_modules/$app`; isolated QA snapshots must keep this generated package private even when sharing unchanged external dependencies. A strict check, production build and unit tests are separate from rendered acceptance and hosted dealer qualification.
