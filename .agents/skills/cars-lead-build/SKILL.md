Read [WORKFLOW](../../../docs/WORKFLOW.md), [the current six-design contract](../../../docs/FLEET-ROLLOUT-2026-10-11.md), [lead guardrails](../../../docs/LEAD-BUILD-GUARDRAILS.md) and the selected dealer's manifest/brief/metadata. The offer is Auto Best, Modern, Import, App, Mobile and Signature (`karento-best`) through one Cloudflare Worker, with all applications/assets, the six-design FAB and shared public Admin demo. Carwow is preserved history, excluded from current choices.

Resolve the business against the registry, aliases and accessible CRM before creating source. Preserve an existing Modern/Import choice at /variant-2; use the other at /variant-3, App at /variant-4, Mobile at /variant-5 and Signature at /variant-6. New dealers default to Modern then Import. Private CRM/outreach history does not belong in public research or dealer exports.

Use the maintained Cars checkout and existing preparation/creator tools; preserve concurrent changes and do not create another editable repository or dependency copy. Read current command help. For direct creator planning, use explicit six-design inputs:

```powershell
node scripts/new-client.mjs --client <slug> --repository <owner/repo> --design-set six --locale-config <en-bg-locale.json> --dry-run
```

The direct creator's default remains a legacy trio, so never omit `--design-set six` for a current proposal. Continue the authorized build through the maintained preparation workflow and its reviewed manifest, rather than inventing a second generator. It verifies source identity, committed inputs and drift before copying. Complete source qualification/release selection when needed under [TEMPLATE-PROMOTION](../../../docs/TEMPLATE-PROMOTION.md); an old approved lock does not certify newer local work. Never bypass an unexplained hold or relabel loose working files as an immutable release.

Freeze one dated, sourced business/inventory/media pack across all six designs. Require factual year, mileage/unit, price/currency and contacts where the actual adapter needs them; preserve unknown values or hold incompatible inputs instead of inventing facts. Retain real sources and stock/demo meaning. Apply through the existing typed boundaries, preserving each template's native palette, composition and routes.

Follow [LEAD-BRANDING](../../../docs/LEAD-BRANDING.md): visually research the real identity; generate required transparent raster logo proposals/treatments with actual metadata and versioned inputs; bind on-light/on-dark/on-accent and every visible consumer. Do not use a hidden logo node, CSS filter or fabricated model-version claim as completion evidence. Generated identities remain proposals.

For corrections, edit the canonical `clients/<slug>/` source and reconcile publishing-only fixes first. Preserve independent ownership, customization, factual content, Vercel identities and old release evidence. Shared template polish belongs in `templates/<key>`.

Use change-sized [QA](../../../docs/QA.md), stable dependencies/previews and one bounded generated output per active owner. At the release checkpoint verify all six mounted apps/assets, logo surfaces, FAB/Admin, safe demo actions, locales and relevant mobile/desktop journeys. Source/build/provider/public alias/hosted acceptance are separate facts. Failed retry candidates retain recovery evidence; follow the existing exact-owner/source resume contract instead of deleting or copying around a hold.

A requested new dealer includes scoped source publication, its private publishing repository and a verified hosted proposal unless the owner narrows scope. Follow [LEAD-PUBLISHING](../../../docs/LEAD-PUBLISHING.md) and cars-publish. Refresh actual account capacity and active Workers Paid evidence before provider writes; purchase intent is not proof. Billing/DNS changes and outreach require their own scope.

Return actual source/export commits, the verified URL, checks and unresolved evidence. Update the technical registry without inventing CRM history, dealer approval or owner visual acceptance.
