# Dealer publication

Read [LEAD-PUBLISHING](../../../docs/LEAD-PUBLISHING.md), the selected `dealer.json`, metadata and technical registry. Resolve exact canonical source, repository, branch, Vercel project/team and intended scope. An audit/status request is read-only. Do not create new identities for occupied dealers.

Use the committed canonical source and versioned `package-dealer.mjs` to produce a fresh derived package; validate the actual standard or Import trio. Preserve full Modern workspace and declared shared assets. Source files and a passing build are not hosted evidence.

Run `export-dealer.mjs` in proposal mode. Review the exact remote head and every unmatched publishing-only change; backport or represent real fixes in tested packaging. Initial migration requires explicit path dispositions tied to candidate digest and remote commit. Do not force-push. Create the scoped export commit with `--write`, then push its receipt only within already authorized scope; a changed remote requires re-export.

Use the existing Git-to-Vercel trigger once. Inspect the deployment for the exported SHA and verify the real public routes/assets/switcher using [QA](../../../docs/QA.md). Keep preview branch pilot and production changes distinct. Do not send external test enquiries.

Update exact source/template/export/package/deployment identities and separate evidence in the technical registry. Return one verified origin, commits, actual checks and gaps. Publication never implies outreach or owner visual approval; do not mass-deploy other dealers.
