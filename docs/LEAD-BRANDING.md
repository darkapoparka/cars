# Lead branding: native palettes and explicit image surfaces

Owner instruction: 11 October 2026. This supersedes older wording allowing automatic dealer theme-colour personalization.

## Contract

A lead changes sourced identity, logo assets, stock, photos, copy, contacts and metadata. It does not redesign or recolour template heroes, banners, major surfaces, controls, spacing or typography. Use the exact selected template's colours. Palette extraction from logos must never drive template UI tokens. The shared Modern/Import adaptation code no longer injects dealer accent values.

New six-design manifests from new-client.mjs and the Varna factory require branding.required and the surface-binding contract. The shared package-dealer.mjs collector keeps the original locale facts and .cars-branding.json, and rejects a required contract that is missing or invalid. Existing live releases are not silently regenerated by this policy.

## Asset workflow

Research and retain the real dealer identity. For an unsuitable logo or a new authorized demo identity, use image generation; keep the returned master, actual generation metadata and source provenance. Never claim a model version the tool did not expose. Record native raster dimensions honestly: increasing export dimensions does not create new detail. Review spelling, padding, transparency, shape, small-size legibility and clipping on actual pages.

Use one identity to produce matched transparent on-light (dark ink) and on-dark (white ink) WebP/PNG exports plus compact marks and favicon/touch icons. Paths are content-versioned under /dealer-brand/v2-<packId>/. Keep original assets separately. Do not use CSS filters as the final replacement for the matching raster variant.

The six-family implementation is scripts/publishing/lead-branding.mjs. Its applyLeadBranding operation validates the inputs, preserves template colour sequences and source-fact hashes, writes identical source-bound packs into each public root and records the consumer references. scripts/publishing/logo-surface-bindings.mjs binds Modern's inverseLogo through logoInversePath and Mobile's desktop hero through a responsive picture source. Surrounding template composition stays unchanged.

The contract must accompany the source and all actual public assets. Generate and review the pack before marking personalization complete, reseal changed native-family source receipts, and keep readyToPublish false until the exact build and hosted checks have succeeded. Unknown permissions and dealer approval remain unknown; a proposed refresh is not an official dealership logo.

## Publication gates

Required checks reject missing or changed raster bytes, wrong dealer/pack identity, unversioned consumer references, missing inverse/hero bindings, stale template-pin palette proofs, changed protected colour sequences and changed dealer facts. CI runs source/asset, inverse-binding and collector regressions. Do not remove a failing check just to publish.

After deployment, open all six designs in Bulgarian and English on mobile and desktop. Inspect header, footer, hero, sticky and menu consumers. Verify the actual loaded image and painted background; positioned hero artwork may be a sibling or pseudo-element, so ancestor background colour alone is not a reliable contrast measurement. Check noindex, the six-design FAB, Admin, native stock detail and contact routes. No real enquiry is sent in this technical verification.

The automated checks are safeguards, not a claim that every conceivable regression is impossible. Preserve failed evidence, fix the cause, rebuild only from reviewed source and record real provider versions plus fresh browser evidence. Mockups, image-generation posters and CI success cannot substitute for that evidence.
