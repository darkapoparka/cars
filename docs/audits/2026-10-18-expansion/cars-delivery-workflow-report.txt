6. Capacity and the separate two-dealer pilot

Official Cloudflare documentation currently lists 100 Workers on Free and 500 on Paid. Against the supplied account count of 100, adding 400 dedicated Workers reaches 500/500, leaving no spare slots. The preserved Vercel identities do not create Worker headroom. 
Cloudflare Workers docs

Workers Paid has a $5 account minimum, including 10 million requests and 30 million CPU-ms; overages are $0.30 per million requests and $0.02 per million CPU-ms. Direct static delivery is normally free; SSR/Worker invocations and enabled Workers Caching can incur charges. $5 is not an all-inclusive fleet bill. 
Cloudflare Workers docs
+1

I recommend retaining dedicated dealer Workers. A separate two-dealer shared-preview pilot is justified as a measurement exercise because the planned fleet consumes normal account headroom. It needs to demonstrate:

Six real framework adapters: request-scoped facts, stock, logos and routes across the Svelte and Next applications, with explicit treatment of SSR, static and build-baked content.
Tenant isolation: distinct identities and opposite Modern/Import ordering; controlled host/path selection; unknown tenants rejected; no mutable global dealer config or cross-tenant fallback.
Cache and asset isolation: dealer, content version, template release and locale included wherever required; interleaved cold/warm requests, details, errors, cookies and local storage tested.
Actual rollback: retained runnable code/assets and a demonstrated rollback unit. A config pointer alone is insufficient.
Measured output: build time, peak disk, source/dependency/artifact copies, asset duplication, bundle size, startup/memory, CPU/TTFB, request mix and cost against two equivalent dedicated Workers.

A slug input alone establishes none of these properties. The present singleton’s per-application framework namespaces are not proof of tenant isolation.

7. Practical release sequence, retries and hold points

The build side already has useful component-reuse machinery. New-source creation does not yet resume itself. The following sequence preserves that distinction.

1. Freeze one dealer’s ownership and source selection

The coordinating agent records physical L:/CODEX/cars, current main, unrelated dirty paths, dealer identity, Worker/Vercel aliases and the existing Modern/Import order. Reconcile only the nine patch paths; a conflicting dirty hunk is an integration hold.

Use the explicit six-design mode and approved source tuple. Keep editable masters in templates/*; publishing mirrors do not become source masters. Public research stays in leads; private CRM/outreach stays in Airtable/Agency OS.

Hold: ambiguous ownership, occupied foreign candidate, source lease or template selection.

2. Freeze and validate one dated facts/stock pack

Retain source IDs, URLs, dates, currency, original units and imagery provenance. Check all six consumer contracts, especially Modern’s unknown-value limitations and App’s strict schema. Remove inherited contacts, locations, videos, staff and testimonials; keep concise illustrative/demo disclosures in existing slots.

Run available prechecks before materialization. Moving every adapter compatibility check ahead of creation remains follow-up work.

Hold: invented facts, dropped provenance, unsupported unknowns or inherited identity.

3. Produce and review the logo pack

For every new lead, use Image Gen with transparent_background: true. Retain actual generation metadata and native dimensions; preserve sourced identity/provenance, or label the result a proposal. Do not invent an unexposed model version.

Review light, dark, accent and compact treatments. Commit PNG/WebP bytes and versioned paths/hashes, then trace their real consumers.

Hold: absent, opaque/empty, stale, uncommitted or wrong-treatment assets—even when the JSON validates.

4. Prepare, adapt and seal the owned source

Use the appropriate new-approved or existing-refresh path. After factual adaptation, catalogs and branding, recompute native/App/extended seals and the exact retained-file inventory.

For a failed candidate, reconcile its creation/failure receipt and owned paths before bounded continuation. Do not blindly rerun creation or allocate another copy.

Hold: conflicts, changed inputs during preparation, stale seals or unverifiable candidate ownership.

5. Publish exact source and build verified inputs

Under the coordinator’s separate authorization, source publication must bind the accepted commit, family sources, facts/logo digests and toolchain locks. Reuse a passed component only when its original lineage and relevant inputs match.

A changed logo pack normally affects all six copied asset outputs. Re-evaluate those outputs and their consumers; a previous successful build is not reusable merely because the dealer slug stayed the same.

Hold: mismatched source, lock, component proof or artifact identity.

7. Review a specific provider release

Before a later authorized upload, bind the immutable output to fresh target ownership/capacity proof and the prior active version. Preserve independent dealer and Vercel identities.

If an upload outcome is ambiguous, read and reconcile actual provider state before retrying. Do not allocate a substitute identity to bypass uncertainty.

Hold: capacity/ownership uncertainty or missing release authorization. This audit performs no upload.

8. Verify the current alias and obtain owner acceptance

At mobile and desktop widths—including the 320px FAB—exercise all six home/inventory/detail/contact journeys, locales and redirects. Check loaded logo URLs, dimensions, hashes and treatments on active header/footer/hero/sticky/menu/inverse surfaces. Compare displayed facts and stock to the sealed pack.

Test demo forms with outbound submission intercepted: no real enquiry, no outreach, and no false “sent” or “saved” success.

A dealer can be marked delivered only when accepted source, compiled output, active provider version, current public alias, hosted content/logo/form checks and explicit owner approval all agree. A stale logo, wrong contact, missing image, broken route or unapproved result keeps that dealer on hold.
